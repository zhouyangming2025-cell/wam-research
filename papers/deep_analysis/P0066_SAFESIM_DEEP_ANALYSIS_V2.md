# 0. Executive verdict

SAFE-SIM is best understood as a **LEARNED REACTIVE CLOSED-LOOP TRAFFIC BEHAVIOR SIMULATOR WITH PLANNER-CONDITIONED ADVERSARIAL DIFFUSION GUIDANCE**.

It is not primarily a planning WAM that predicts a future state for the ego planner to consume.

Its deployed causal loop is approximately:

```text
current multi-agent scene + map/history
        ↓
ego planner π produces current ego future plan
        ↓
reactive-agent diffusion model g samples non-ego action trajectories
        ↓
planner-conditioned guidance modifies selected adversarial trajectories
        ↓
filter / select trajectory samples
        ↓
execute first few actions for ego + non-ego agents
        ↓
update shared simulation state
        ↓
new observation / new ego plan / new reactive-agent generation
        ↓
repeat
```

The key scientific role is therefore:

```text
SIMULATOR / EVALUATION ENVIRONMENT
```

not:

```text
future representation consumed by planner
candidate scorer inside planner
training-only world-model regularizer
```

The most important new control for the WAM atlas is **reactivity semantics**:

```text
SAFE-SIM does generate endogenous learned surrounding-agent responses
under changed ego plans in closed loop

BUT

it does not provide paired real-world intervention-response truth
for those alternative ego behaviors.
```

Canonical subtype:

> **BEHAVIOR-CENTRIC REACTIVE CLOSED-LOOP DIFFUSION SIMULATOR + ADVERSARIAL SCENARIO GENERATOR**

---

# 1. What problem does SAFE-SIM actually solve?

SAFE-SIM targets **planner evaluation under rare safety-critical interactions**.

The core problem is not:

```text
How should the ego planner choose a trajectory?
```

It is:

```text
How can an evaluator generate realistic, diverse, controllable and interactive traffic behavior
that can repeatedly challenge an ego planner in closed loop?
```

The paper identifies a limitation of static/adversarial scenario generation:

```text
initial adversarial setup
→ planner changes behavior
→ surrounding traffic does not adapt
```

This is scientifically different from a planning-centric WAM failure.

Planning WAMs usually ask:

```text
Can future knowledge improve ego decision quality?
```

SAFE-SIM asks:

```text
Can a learned traffic environment continue reacting after the ego changes its behavior,
and can that environment be steered toward safety-critical outcomes?
```

---

# 2. State, action and physical transition

The simulator contains N agents:

```text
1 ego vehicle controlled by planner π
N-1 non-ego vehicles controlled by reactive behavior model g
```

A vehicle state is represented by:

```text
s_t^i = (x, y, v, yaw)
```

and action by:

```text
a_t^i = (acceleration, yaw-rate)
```

A transition model advances state:

```text
s_(t+1) = f(s_t, a_t)
```

with unicycle-style dynamics at the paper abstraction level.

Each agent's context includes:

```text
agent-centric map
+ historical neighboring-agent states
```

The implementation uses rasterized scene context and past trajectories.

This is a **behavior-state simulator**, not a camera-video simulator.

---

# 3. What exactly is predicted?

The diffusion model predicts **future action sequences for traffic agents**.

Operational trajectory:

```text
τ = [τ_a, τ_s]
```

where:

```text
τ_a = action sequence
τ_s = resulting state sequence
```

The learned model directly predicts the action trajectory, while state trajectories can be generated by forward dynamics.

Therefore the predicted future object is:

```text
NON-EGO AGENT BEHAVIOR / MOTION TRAJECTORY
```

not:

```text
RGB future
BEV feature
occupancy field
planner latent
reward/value
```

This is world modeling in a broad multi-agent dynamics sense, but its scientific function is simulator behavior generation.

---

# 4. The closed loop — paper and code reconstruction

The paper states that each agent continuously regenerates a trajectory from its updated decision context, executes the first few actions, then replans.

The source makes the ordering explicit.

## Per replanning cycle

```text
1. env.get_observation()
2. ego_policy.get_action(...)
3. copy ego_action.positions → agents observation as `ego_plan`
4. agents_policy.get_action(...)
5. env.step(joint action, n_step_action)
6. update physical scene state
7. return to step 1
```

The paper experiment runs both planner and reactive-agent updates at **2 Hz**.

The 2 Hz value is an experiment configuration; the source exposes `n_step_action`, so the framework conceptually supports configurable action execution between model queries.

# 5. Feedback decomposition

Use the project-wide feedback coordinate system:

```text
F_e = ego-state / dynamics feedback
F_s = sensor / viewpoint feedback
F_a = surrounding-agent state feedback
F_b = surrounding-agent behavioral-response feedback
```

SAFE-SIM:

```text
F_e = YES
F_a = YES
F_b = YES
F_s = NO / NOT PRIMARY in the sensor-realistic sense
```

Why F_b is genuinely present:

```text
new ego plan
→ explicitly passed to reactive-agent generation/guidance
→ non-ego trajectory can change
→ resulting agent state enters next scene
```

This is stronger behavioral reactivity than log replay or fixed logged-agent trajectories.

But:

```text
F_b present
!=
intervention truth available
```

The responses are model-generated.

---

# 6. Base behavior model

SAFE-SIM uses a diffusion trajectory model trained on real driving data.

Context representation:

```text
agent-centric raster map
+ historical trajectories
→ ResNet scene encoder
```

Trajectory diffusion:

```text
noisy action trajectory
→ temporal 1D-convolution U-Net
→ denoised action trajectory
```

Paper setting:

```text
K = 100 diffusion denoising steps
```

This introduces one of the ontology's central semantic traps:

```text
K=100 diffusion steps
!=
100 physical-time future steps
```

Diffusion coordinate is an internal optimization/generative coordinate.

Physical future time lives in the predicted action/state horizon and repeated environment execution.

---

# 7. Adversarial guidance

The base diffusion model learns realistic behavior from data. Safety-critical behavior is then steered at inference using differentiable guidance.

Conceptually:

```text
base data-likelihood behavior prior
+
adversarial objective
+
regularization / realism objectives
→ guided adversarial trajectory
```

The paper combines objectives including:

```text
collision / ego-adversary interaction
relative velocity
TTC
route compliance
Gaussian-distance interaction regularization
```

The source shows the current ego plan explicitly enters guidance calculations.

`CauseCollisionLossCalculator` uses:

```text
prediction_mode = "ego_plan"
```

and replaces the ego's future path in pairwise calculations with the currently planned ego trajectory.

TTC guidance similarly inserts the current ego plan.

Thus the adversarial agent is specifically generated **against the current planner trajectory**, rather than simply being a generically aggressive vehicle.

---

# 8. Gradient path

Guidance is an inference-time trajectory optimization inside diffusion sampling.

Code-level path:

```text
sampled reactive-agent action
→ forward dynamics
→ guidance cost
→ ∂cost / ∂sampled action
→ perturb sampled action
→ continue denoising
```

The planner's trajectory is used as a condition/reference in the cost.

No audited gradient path updates ego planner parameters.

Therefore:

```text
planner → adversarial generator condition       YES
adversarial guidance → planner parameters       NO
```

SAFE-SIM is not jointly training the planner and simulator.

---

# 9. Multiple samples and filtering

During inference the simulator generates multiple future trajectories for reactive agents.

It then uses guidance cost to select a trajectory sample.

Therefore the simulator's deployed output is shaped by three distinct mechanisms:

```text
1. learned diffusion distribution
2. gradient guidance
3. sample filtering / selection
```

This matters for attribution: simulator behavior should not be attributed to diffusion learning alone.

---

# 10. Partial diffusion

Partial diffusion is a second controllability mechanism.

First construct a domain-informed collision trajectory proposal from:

```text
ego/adversary centerlines
+ their possible intersection
+ acceleration
+ lateral offset
+ current/projected ego plan
```

Then:

```text
proposal τ0
→ choose partial diffusion ratio γ
→ noise to internal step k_p = γK
→ guided denoise from k_p back toward a realistic trajectory
```

Interpretation:

```text
small/noise setting
→ stronger proposal control

more noise
→ stronger pull back toward learned data distribution / greater stochasticity
```

The proposal is updated during closed-loop interaction.

This is not partial physical simulation; it is initialization inside the diffusion noise coordinate.

# 11. Reactivity: what is strong and what remains unproven?

## Strong evidence

SAFE-SIM is operationally reactive because:

```text
ego planner is queried repeatedly
reactive agent model is queried repeatedly
updated ego plan explicitly enters agent generation
updated environment state is fed into the next cycle
```

The model therefore does not merely replay logged non-ego future trajectories.

## Missing evidence

For an alternative ego action a', the paper does not provide:

```text
same real scene
+ actual intervention ego action a'
+ measured surrounding-agent response Y(a')
```

Therefore the model's generated response is not directly supervised/validated against paired intervention outcomes.

Canonical project distinction:

```text
reactive behavior generation             YES
conditional response model               YES
intervention-ground-truth identification NO
causal counterfactual truth              NO
```

# 12. Training data and transfer

The behavior model is trained on **nuScenes train split**.

Evaluation includes:

```text
nuScenes validation
nuPlan mini validation
```

The paper states that nuPlan evaluation is performed without additional fine-tuning.

This provides evidence of some cross-dataset behavior-model transfer.

It does not prove:

```text
universal traffic-behavior generalization
or
counterfactual response correctness on nuPlan
```

---

# 13. Evaluation metrics

SAFE-SIM evaluates two main properties:

## Realism

Distributional realism uses Wasserstein distance between simulated and logged driving-profile histograms for:

```text
longitudinal acceleration
lateral acceleration
jerk
```

Lower is better.

It also tracks off-road/collision behavior.

This is **distributional motion realism**, not paired future prediction error and not behavioral counterfactual accuracy.

## Controllability

Metrics include:

```text
TTC-related cost
collision relative speed
collision angle
collision-point diversity
within-scenario collision diversity
```

These quantify whether user/guidance parameters can change safety-critical outcomes.

# 14. Main baseline evidence

Rule-based planner comparison:

```text
nuScenes
SAFE-SIM   Collision 43.2% | Other offroad 1.8% | Adv offroad 11.4% | Realism 0.38
STRIVE     Collision 36.4% | Other offroad 2.2% | Adv offroad 11.4% | Realism 0.85
DiffScene  Collision 18.2% | Other offroad 11.4%| Adv offroad  9.0% | Realism 0.52
```

nuPlan zero-shot transfer:

```text
SAFE-SIM   Collision 80.0% | Other offroad 9.4% | Adv offroad 11.7% | Realism 0.27
DiffScene  Collision 56.7% | Other offroad14.0% | Adv offroad  5.0% | Realism 0.42
```

Direct interpretation:

```text
SAFE-SIM produces more adversarial collisions while maintaining better aggregate motion-profile realism than the tested baselines in these settings.
```

Do not transform that into:

```text
SAFE-SIM is causally more realistic under ego interventions
```

because that is not what the realism metric measures.

# 15. Different-planner experiment

The simulator is tested against different ego planners.

Reported Ego–Adversary collision rates include:

```text
BC          38.8%
IDM         49.3%
Lane-Graph  34.3%
BITS        16.4%
PDM-Closed  26.9%
```

Scientific value:

```text
the adversarial simulator can condition on and challenge multiple planner families
```

But these rates are **not a clean planner ranking** because:

```text
the adversary adapts to the planner
metrics include attack-generation dynamics
planner interfaces / assumptions differ
failure attribution is not fully controlled
```

The paper itself notes failure cases where the ego may not be at fault.

---

# 16. TTC controllability

Increasing TTC guidance weight changes adversarial outcomes:

```text
TTC weight       0.0    1.0    2.0
Collision rate   48.2   53.6   60.7
Realism          0.76   0.79   0.81   (lower is better)
```

This demonstrates control over safety-criticality, but also hints at a realism-control trade-off:

```text
stronger adversarial pressure
→ higher collision rate
→ slightly worse aggregate realism metric
```

This should not be hidden by the paper's overall `realistic and controllable` framing.

# 17. Partial diffusion / regularization ablation

Reported ablation:

```text
Jadv + Jreg, no partial diffusion
Collision 23.9 | Adv offroad 13.8 | Realism 0.58 | collision-point variance 1.62

Jadv + Jreg + partial diffusion
Collision 29.0 | Adv offroad 14.6 | Realism 0.57 | collision-point variance 5.44

Jadv only
Collision 53.5 | Adv offroad 23.1 | Realism 0.58 | relative-speed variance 4.81
```

Strongest conclusions:

```text
partial diffusion materially increases collision-location/type diversity
```

and:

```text
removing regularization raises attack/collision rate
but also increases invalid/off-road adversarial behavior
```

Therefore maximizing planner failure is not equivalent to generating a better simulator.

---

# 18. Failure cases

The paper explicitly reports:

```text
adversarial agent may unrealistically collide with non-adversarial traffic before ego
some generated collisions are not attributable to ego-planner fault
```

These failures are scientifically important because they show the limit of using collision generation as planner-quality evidence.

A safety-critical simulator needs both:

```text
challenge effectiveness
and
behavioral validity / fault validity
```

SAFE-SIM primarily demonstrates the former plus distributional realism proxies; it does not fully solve fault-valid counterfactual evaluation.

```text
→ explicit future risk
→ no ego-action-conditioned planner loop

SAFE-SIM
current scene + current ego planner action

```

Key contrast:

```text
RiskWorld = stronger factual future supervision, weak/no intervention loop
SAFE-SIM  = stronger intervention/reactivity loop, weaker factual counterfactual truth
```

This establishes a major field distinction:

```text
future factual accuracy
and

```

# 20. SAFE-SIM vs SafeDrive

```text
SafeDrive
candidate ego trajectory
→ candidate-conditioned sparse consequence representation
→ safety/value score
→ choose ego trajectory

SAFE-SIM
ego planner chooses trajectory
→ surrounding behavior simulator reacts / adversarially responds
→ evaluate resulting closed-loop episode
```

SafeDrive is **inside planning selection**.

SAFE-SIM is **outside the planner as an evaluation environment**.

SafeDrive candidate-specific non-ego futures are not validated as reactive intervention truth; SAFE-SIM has genuine repeated response feedback, but still lacks paired real-world intervention truth.

# 21. SAFE-SIM vs WoTE / DA-WAM

WoTE / DA-WAM:

```text
candidate_i
→ future_i
→ value_i
→ argmax candidate
```

SAFE-SIM:

```text
chosen/planned ego action
→ environment agents react
→ physical scene advances
→ planner replans
```

This is a fundamental role difference:

```text
planning-time hypothetical evaluation
vs
closed-loop external environment simulation
```

WoTE/DA-WAM can evaluate many candidates cheaply within one planning step.
SAFE-SIM runs a sequential environment interaction around an already operating planner.

# 22. SAFE-SIM vs DriveReward

```text
DriveReward
current context + candidate ego trajectory
→ direct value/reward

SAFE-SIM
current context + ego plan
→ generated surrounding behavior
→ future interaction episode
```

This is another clean separation:

```text
compressed learned value
vs

```

DriveReward is useful for efficient policy training/ranking; SAFE-SIM is useful for behavioral stress testing.

# 23. SAFE-SIM vs sensor-realistic simulators

SAFE-SIM primarily models traffic-agent behavior in state/raster space.

A simulator such as HUGSIM / neural-rendering closed-loop systems focuses much more strongly on:

```text
sensor viewpoint
photorealistic rendering
camera feedback under ego motion
```

SAFE-SIM's strength is instead:

```text
learned surrounding-agent behavior
+ planner-conditioned adversarial interaction
```

Thus:

```text
sensor realism
!=
behavioral reactivity
```

A simulator may be strong on one and weak on the other.

---

# 24. What SAFE-SIM proves

The audited evidence supports:

1. a diffusion-based traffic behavior model can be embedded in a repeated closed-loop planner/agent simulation;
2. current ego planner output can explicitly condition adversarial non-ego generation;
3. test-time differentiable guidance can steer learned behavior toward planner-specific collisions;
4. partial diffusion provides meaningful control over collision type/location diversity;
5. regularization is important for reducing invalid/off-road adversarial behavior;
6. the reported learned simulator transfers from nuScenes training to nuPlan-mini evaluation without fine-tuning in the tested setup;
7. SAFE-SIM can challenge multiple planner families rather than only one fixed planner.

---

# 25. What SAFE-SIM does NOT prove

It does not establish:

1. paired ground-truth responses of other agents under alternative ego interventions;
2. causal correctness of generated reactions;
3. planner ranking validity from induced collision rate alone;
4. sensor-realistic camera/LiDAR closed-loop simulation;
5. real-vehicle closed-loop planner safety;
6. calibrated response uncertainty;
7. that stronger adversarial success always means greater realism;
8. that a simulator trained on observational trajectory data correctly extrapolates to every aggressive ego behavior;
9. that planner gradients are propagated through the simulator;
10. that SAFE-SIM is a planning WAM merely because it predicts future traffic behavior.
