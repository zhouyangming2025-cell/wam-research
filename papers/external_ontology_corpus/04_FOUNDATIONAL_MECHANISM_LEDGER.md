# Foundational Mechanism Ledger

Status: first ontology-free external pressure-test batch.

This ledger is intentionally written without R/W/E/L codes. The last column records **pressure on candidate ontologies**, not a final classification.

## 1. Dyna — model-assisted learning with reactive execution

**Source:** Sutton, 1991, *Dyna, an Integrated Architecture for Learning, Planning, and Reacting*.

**Reading depth:** RD2 for architecture-level mechanism.

### Mechanism

```text
real experience
→ learn value/policy
→ learn action-effect model

learned model
→ simulated/planning experience
→ additional value/policy updates

runtime execution:
perception → compiled value/policy → action
```

Primary-source abstract explicitly states that planning can use learned probabilistic world models, while execution is fully reactive: no planning intervenes between perception and action.

### Ontology pressure

- proves `world model used in learning/planning` and `world/model object used online between perception and action` are distinct questions;
- strongly supports a deployment-world-use dimension analogous to current W0 versus online-world categories;
- world knowledge may be compiled into policy/value without a runtime model state on the immediate action path;
- learning-route ontology must preserve `model → synthetic/planning updates → deployed policy/value`.

## 2. Value Prediction Network (VPN) — abstract dynamics without observation reconstruction

**Source:** Oh, Singh, Lee, NeurIPS 2017.

**Reading depth:** RD2; primary paper method inspected.

### Explicit objects

```text
observation x
→ encoder
→ abstract state s

(s, option o)
→ outcome module → reward r, discount γ
→ transition module → next abstract state s'
→ value module on s'
```

The paper states that the abstract state is **not** the environment state nor an approximation to it. It is trained so that option-conditioned rollouts predict rewards, discounts and values.

### Online planning

The core module is recursively unrolled in abstract-state space for multi-step lookahead. Planning aggregates intermediate value estimates to choose options.

### Ontology pressure

- falsifies a gate that requires RGB/observation/factual-future reconstruction for an object to count as a planning world/model state;
- a useful world-model state can be **decision-sufficient rather than observation-sufficient**;
- multi-step abstract rollout belongs with future rollout/search mechanisms even though no image/world scene is rendered;
- criterion semantics include reward/value and should not be forced into `fidelity to future observation`.

---

## 3. TreeQN / ATreeC — learned abstract transition inside differentiable search tree

**Source:** Farquhar et al., 2018.

**Reading depth:** RD2 from primary abstract/method-level description.

### Mechanism

```text
observation
→ learned abstract state

for each candidate action:
abstract state
→ learned transition
→ predicted reward + next abstract state
→ recursively expand lookahead tree

leaf/state values
→ differentiable tree backup
→ Q-values / policy
→ action
```

The learned transition is optimized for its use in the tree rather than for observation reconstruction.

### Ontology pressure

- action formation can be **search/tree backup**, not direct action, semantic hierarchy, or finite candidate-bank→resolver in the current driving sense;
- a human R dimension derived only from the original 12 driving artifacts is likely incomplete unless it can express search/optimization;
- physical-future temporal depth and search-tree depth are related but not identical clocks;
- branching/search structure may need an audit attribute even if not a new top-level axis.

---

## 4. World Models — predictive recurrent hidden state consumed by controller

**Source:** Ha & Schmidhuber, 2018.

**Reading depth:** RD2.

### Mechanism family

```text
observation
→ VAE latent z_t

(z_t, action history, recurrent dynamics)
→ predictive RNN hidden h_t

controller consumes [z_t, h_t]
→ action
```

The world model learns compressed spatial and temporal representations. Policies can also be trained inside hallucinated rollouts generated by the learned model.

### Ontology pressure

- distinguishes a plain current observation representation `z_t` from a predictive recurrent hidden state `h_t`;
- supports retaining a category for **predictive internal state consumed directly by policy without materializing a future endpoint at runtime**;
- also contains a separate `train policy inside generated world` route, showing one paper can instantiate multiple artifact mechanisms;
- implementation substrate `latent` is insufficient to classify either object.

---

## 5. PlaNet — latent dynamics used for online action-sequence planning

**Source:** Hafner et al., ICML 2019, *Learning Latent Dynamics for Planning from Pixels*.

**Reading depth:** RD2 mechanism-level reconstruction.

### Mechanism

```text
observation history
→ recurrent state-space model state

sample candidate action sequences
→ roll each sequence through learned latent dynamics
→ predict cumulative reward
→ cross-entropy-method update of action-sequence distribution
→ execute first action
→ replan next environment step
```

### Ontology pressure

- exposes a major action-formation topology absent from the current 12-paper R examples: **continuous/search optimization over action sequences using model rollouts**;
- online future world/model objects are multi-step latent consequences, not merely a single endpoint;
- resolver/criterion is return optimization, but the alternatives may be regenerated iteratively rather than a persistent semantic bank;
- MPC/receding-horizon clock must not be confused with modeled physical horizon or numerical optimizer iterations.

---

## 6. Dreamer — imagined trajectories train actor and value functions

**Source:** Hafner et al., ICLR 2020, *Dream to Control: Learning Behaviors by Latent Imagination*; later Dreamer variants retained as follow-up evidence.

**Reading depth:** RD2.

### Mechanism

Training:

```text
real observations/actions
→ learn latent world model

current model states
→ imagine latent future trajectories under actor
→ predicted rewards/continuations
→ train value model + actor
```

Deployed interaction can then use the learned actor on current model state rather than running a fresh CEM/MCTS search for every action.

### Ontology pressure

- world-model usage during **policy learning** must be distinguished from world rollout during **decision-time action search**;
- a runtime current model state may remain online even when future imagination is training-only;
- current W categories need a clean rule for `current learned model/belief state consumed by actor` versus generic perception feature;
- L must represent `imagined trajectories → actor/value learning → deployed actor` without misclassifying the imagined futures as runtime world objects.

---

## 7. MuZero — planning-sufficient learned model + MCTS

**Source:** Schrittwieser et al., Nature 2020 / arXiv 1911.08265.

**Reading depth:** RD2.

### Mechanism

```text
history/observation
→ representation h
→ root hidden state s0

MCTS repeatedly applies:
(s, action)
→ dynamics g
→ next hidden state + reward
→ prediction f
→ policy prior + value

search statistics / backed-up values
→ root action
```

The learned model predicts quantities directly relevant to planning—reward, policy and value—without requiring knowledge/reconstruction of the environment's full underlying dynamics.

### Ontology pressure

- confirms VPN lesson at much larger scale: a valid planning model can be **planning-sufficient and observation-incomplete**;
- runtime action formation is tree search, not candidate-bank scoring in the narrow driving sense;
- `world representation type` and `decision coupling/search topology` must remain separate dimensions;
- a future rollout category should admit branching hidden-state trees, not only physical-frame sequences.

---

## 8. TD-MPC / TD-MPC2 — local trajectory optimization in implicit latent world model

**Source:** Hansen et al., TD-MPC (2022); TD-MPC2 (ICLR 2024).

**Reading depth:** RD2 from primary abstract/method descriptions.

### Mechanism

```text
observation
→ latent state

candidate action sequences / policy prior
→ learned latent dynamics rollout
→ reward / value / Q estimates
→ local trajectory optimization
→ first action
```

TD-MPC2 explicitly describes local trajectory optimization in the latent space of a learned **implicit, decoder-free world model**.

### Ontology pressure

- directly falsifies any world-state gate that requires image/observation decoding;
- shows `decoder-free` is an implementation property, not absence of a world model;
- reinforces the need for an optimization/search form of action commitment distinct from static bank→argmax;
- value and terminal-value semantics are first-class decision criteria.

## 9. Predictive State Representations — theoretical boundary case

**Source family:** Littman, Sutton, Singh and subsequent PSR literature.

**Reading depth:** RD1 in this batch; promote to RD3 before using for a normative definition.

### Mechanism idea

A system state can be represented by predictions of future observable outcomes/tests rather than by an inferred hidden physical state.

### Ontology pressure

- warns against defining world state by resemblance to physical scene variables;
- `state` should be characterized by its predictive/dynamical role and sufficiency, not visual interpretability;
- relevant to defining current-state categories without equating them to BEV/agent/map features.

---

## 10. V-JEPA 2 / action-conditioned JEPA family — predictive representation without generative pixels

**Source family:** Meta V-JEPA/V-JEPA 2 and action-conditioned embodied variants.

**Reading depth:** RD1–RD2 boundary in this batch; promote before final verdict.

### Mechanism idea

Predict future representations in embedding space; action-conditioned variants use predictive latent dynamics for embodied planning/control while avoiding full pixel reconstruction.

### Ontology pressure

- independently supports `predictive grounding != reconstruction`;
- future-representation prediction can be planning-relevant even when visual generation is absent;
- strengthens invariance requirement across RGB generation versus latent predictive semantics.

# Cross-paper conclusions from foundational batch

## F1 — A deployment-world-use question is necessary

Dyna versus PlaNet/MuZero is decisive:

```text
Dyna execution: model results compiled into policy/value; no planning between perception and action
PlaNet/MuZero: learned model actively used in online decision computation
```

A human-level ontology that cannot state this difference loses a central model-based-control distinction.

## F2 — Reconstruction cannot define a world/model state

VPN, MuZero, TreeQN and TD-MPC2 all make the point from different directions. A model state may be abstract and trained only for reward/value/planning utility.

## F3 — `current model state`, `predictive internal state`, `future endpoint`, and `rollout/search structure` remain promising distinct temporal/causal roles

But their definitions must be mechanism-based rather than representation-based.

## F4 — Current R is under pressure

The original driving-derived R set lacks a clean human-level home for:

```text
MPC / iterative trajectory optimization
MCTS / tree search
learned lookahead / differentiable tree backup
```

Forcing these into RB would overstate identity-preserving candidate-bank semantics; forcing them into R0 would erase online deliberation/search.

This is a high-priority external-axis discovery issue.

## F5 — Current E is under pressure from planning/search

Current E was designed around a separate resolver. Model-based planning often embeds criterion semantics inside:

```text
return maximization
value backup
Q evaluation
terminal value
reward + continuation
```

A human criterion dimension remains useful, but its applicability should likely be generalized from `resolver criterion` to **decision objective / commitment criterion**, covering both bank resolution and online search/optimization.

## F6 — Learning/deployment separation is strongly validated

Dyna and Dreamer independently support the core idea behind L and runtime W separation: learned world dynamics can shape the eventual policy without being replayed as explicit future rollouts during each deployed decision.
