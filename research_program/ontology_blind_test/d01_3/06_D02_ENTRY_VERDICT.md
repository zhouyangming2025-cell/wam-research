## What passed substantively

- GraphAD demonstrates that an explicit future motion sequence used to build a planning interaction graph fits the existing direct future-horizon route without being inflated into candidate selection or reciprocal world/policy refinement.
- DriveDreamer demonstrates that terminal future-video generation and joint future-video/future-action generation can be represented using existing generation and joint-emission forms. Its action-only deployment boundary remains an honest UNKNOWN.
- DrivoR demonstrates that an explicit candidate bank and decomposed driving-outcome scorer can coexist with W0 when no separately predicted world/consequence carrier exists. This is an important negative-boundary test.
- The blind set therefore exercises carrier admission, generation-only terminal output, joint emission, W0 candidate resolution, and the D3/RR anti-overclassification rule.

## Evidence-limited items

1. GraphAD: occupancy post-optimization and exact iterative deployment semantics are not code-verified.
2. DriveDreamer: no local code commit was inspected; the fate of the video decoder in action-only planning is unresolved.
3. DrivoR: no local code commit was inspected; undocumented project-page post-processing remains UNKNOWN.

These are evidence limits, not abstraction failures. The required follow-up is evidence upgrade, not ontology expansion.

## D02 entry rule

Because the verdict is a blind pass with evidence limitation, D02 may begin only with the following controls:

- shallow one-row census of 80–120 papers, in waves of 20;
- freeze the ontology inside each wave;
- run collision and false-split checks after every wave;
- use UNKNOWN when the paper or code cannot close a field;
- do not create full ontology-free cards for ordinary papers;
- elevate only boundary, collision, UNKNOWN, or representative-route papers to deeper audit;
- amendments, if ever needed, are proposed only at wave boundaries and never applied automatically;
- no new dimension may be added merely because corpus size grows;
- final output remains functional route families plus evidence boundaries, not paper-specific signatures.

This document authorizes discussion of those D02 controls only. It does not execute D02 and does not promote the ontology to S2/S3.
